# CVE 5.1 지원 추가

공식 자료의 형식 때문에 필요한 CVE를 정리하지 못하는 문제를 줄이기 위한 변경이다. 5.1과 기존 5.2를 각각 확인한 규칙으로 검사함.

| 원본 dataVersion | 사용할 공식 규칙 | 처리 |
|---|---|---|
| 5.1 | 5.1.1 | 구조가 맞으면 정리함 |
| 5.2 | 5.2.0 | 기존 방식대로 정리함 |
| 5.0 | 아직 정리 미지원 | 원본 수집 후 미지원으로 남김 |
| 그 밖의 값 | 지원하지 않음 | 자동으로 추측하거나 바꾸지 않음 |

5.1.1은 공식 규칙의 배포 번호이며 원본 dataVersion 값을 5.1.1로 바꾸라는 뜻이 아님.

## 실제 처리 순서

원본과 수집 기록 확인 → 원본의 dataVersion 읽기 → 해당 공식 규칙의 파일 확인값 확인 → 구조 검사 → 기관별 항목 정리 → 새 결과 폴더에 저장함.

여러 건을 처리한 뒤에는 원본·수집 기록·정리 결과의 dataVersion이 같은지, 기록된 규칙의 버전·출처·확인값도 맞는지 확인함. 파일 형식 검사를 통과했다는 뜻이며 취약점의 사실 여부나 내 컴퓨터의 영향 여부를 판단한 것이 아님.

## 직접 설명할 예시

- 공식 CVE-2021-32803 원본은 5.1임. 이전 정리기는 지원하지 않았고, 이번에는 5.1.1 공식 규칙을 사용해 node-tar와 영향을 받는 버전 정보를 보존함.
- 원본의 `< 3.2.3` 같은 버전 범위 문장은 그대로 보관함. 이번 단계에서 설치된 버전과 비교하거나 실행을 막지 않음.
- 5.2 자료는 기존 5.2.0 규칙으로 확인함. 기존 원본이나 이전 정리 결과를 새 자료로 덮어쓰지 않음.

## 시험

```bash
.venv/bin/python -m unittest discover -s collector -p 'test_*.py' -v
```

전체 시험에는 실제 저장 자료를 사용하는 경우와 오류 상황을 만든 시험이 함께 있음. 시험 수를 CVE 수로 해석하지 않음. 실제 5.1 원본과 출처는 `fixtures/CVE-2021-32803.json`, `fixtures/SOURCE-5.1.json`에 있으며 변형한 시험 자료는 임시 폴더에만 작성함.

이전 README-step2·step3은 그 단계의 이력임. 현재 지원 범위는 이 문서를 기준으로 읽음. readyForMatching=false와 제품 버전 0.3.0을 유지함.
