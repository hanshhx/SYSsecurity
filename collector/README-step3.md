# v0.4 세 번째 단계: CVE 목록 수집·정리

`batch_cves.py`는 텍스트 목록의 CVE를 하나씩 수집하고 공식 형식으로 검사·정리한다. 첫 단계의 `fetch_cve.py`와 두 번째 단계의 `normalize_cve.py`를 그대로 호출한다. 기존 원본·영수증·이용 고지와 정리 결과를 바꾸지 않고 이번 실행의 결과를 새 폴더에 모은다.

이번 기능은 자료 준비 단계다. 설치된 프로그램·버전 대조, 실행 허용·경고·차단, OSV 연결을 수행하지 않는다. 모든 배치와 항목의 `readyForMatching`은 `false`다. `NORMALIZED`도 안전 판정이나 실행 후보 선정 결과가 아니다. 제품 버전을 올리거나 v0.4 전체 완료로 처리하지 않는다.

## 실행

앞 단계의 파일과 Python 의존성이 설치된 프로젝트 폴더에서 실행한다. 새 Python 패키지를 추가하지 않는다.

```bash
.venv/bin/python collector/batch_cves.py \
  --list collector/examples/cve-step3-small.txt \
  --output-root reports/cve-batches \
  --timeout 45 \
  --pause 1
```

`--list`는 필수다. 나머지를 생략하면 프로젝트의 `reports/cve-batches`에 저장하며, 건별 제한은 45초, 건 사이 대기는 1초다. 현재 Python으로 자식 Python을 실행하므로 `.venv/bin/python`을 사용하면 자식도 같은 의존성을 사용한다.

목록은 UTF-8 텍스트이며 한 줄에 CVE 번호 하나를 쓴다. UTF-8 BOM과 LF·CRLF 줄바꿈을 허용한다. 빈 줄과 첫 글자가 `#`인 주석 줄을 건너뛴다. 앞뒤 공백은 제거하며, CVE 번호 뒤의 같은 줄 주석은 허용하지 않는다.

```text
# 공개 자료 세 건으로 설치 상태를 확인함
CVE-2025-55130
CVE-2025-55131
CVE-2025-55132
```

목록 전체를 확인한 다음에만 출력 폴더 생성과 네트워크 요청을 시작한다. 잘못된 번호가 한 줄이라도 있으면 앞의 정상 번호도 요청하지 않는다. 중복은 처음 등장한 순서대로 한 번만 요청하고, 중복 번호·현재 줄 번호·첫 줄 번호를 `input.duplicates`에 남긴다.

과도한 입력을 제한하기 위해 목록은 256 KiB, 10000줄, 중복 제거 후 1000개 이하여야 한다. 1000개는 한 배치의 상한이며 연구 자료 60~100건 목표를 달성했다는 뜻이 아니다. 작은 예제 목록과 합성 시험 자료도 목표 수집 건수로 계산하지 않는다.

## 결과와 상태

매번 `reports/cve-batches/batch-임의값/`을 새로 만든다. 각 번호에는 별도 하위 폴더를 주며 기존 수집기가 그 안에 고유한 수집 폴더를 만든다.

```text
reports/cve-batches/batch-임의값/
  checkpoint.json
  batch.json
  records/
    0001-CVE-2025-55130/
      worker-result.json
      CVE-2025-55130-임의값/
        original.json
        receipt.json
        CVE_LICENSE_NOTICE.txt
        normalized-v1-임의값/
          normalized.json
          CVE_LICENSE_NOTICE.txt
```

실패한 단계에 따라 파일 일부가 없거나 `failure.json`이 남을 수 있다. 폴더가 있다는 사실만으로 성공으로 취급하지 않는다. `batch.json`의 `items`가 안내하는 경로를 사용한다. 모든 경로는 해당 배치 폴더를 기준으로 한 상대 경로다. 수집 완료 폴더를 얻기 전에 실패하면 `collectionPath`는 그 번호의 상위 폴더를 가리킨다.

| 항목 상태 | 뜻 | 결과 처리 |
| --- | --- | --- |
| `NORMALIZED` | PUBLISHED 기록이 공식 5.2 규칙 검사와 정리를 통과함 | 원본·수집 기록·정리 결과를 보존함 |
| `REJECTED` | 공식 5.2 규칙을 통과한 철회·거부 기록임 | 거부 이유를 보존함. 실행 후보로 사용하지 않음 |
| `UNSUPPORTED_FORMAT` | 현재 정리기가 지원하지 않는 형식임 | 정리 성공으로 집계하지 않음 |
| `FAILED` | 통신·JSON·공식 규칙·저장·자식 결과 확인 등이 실패함 | `errorCode`와 남은 파일로 원인을 확인함 |
| `TIMEOUT` | 수집·정리 자식 프로세스가 전체 시간 제한을 넘음 | 자식을 종료하고 다음 번호를 처리함 |

첫 수집기는 기본 구조 5.0·5.1·5.2를 읽지만, 정리기는 확인된 5.2만 지원한다. 따라서 5.1 자료는 원본·수집 영수증·고지를 보존한 뒤 `UNSUPPORTED_FORMAT`이 된다. 첫 수집기가 모르는 형식은 그 단계에서 거부되어 원본이 저장되지 않을 수 있다. 이번 변경은 형식 지원 범위를 넓히지 않는다.

`batch.json`의 기본 계약은 다음과 같다.

- `formatVersion`: `syssecurity.cve.batch.v1`
- `batchStatus`: 전체 순회 후 `COMPLETED` 또는 `COMPLETED_WITH_ERRORS`
- `readyForMatching`: 항상 `false`
- `input`: 입력 파일의 `sha256`, `bytes`, `lineCount`, 중복 포함 `inputCount`, `uniqueCount`, `ids`, `duplicates`
- `settings`: 건별 제한 시간, 건 사이 대기 시간, `automaticRetries: 0`
- `counts`: 위 다섯 항목 상태별 개수
- `items`: 입력 순서대로 `cveId`, `status`, `collectionPath`, `readyForMatching`; 해당하는 경우 `normalizedPath`, `errorCode`
- `startedAt`, `completedAt`: 시간대가 포함된 UTC 시각

`COMPLETED`는 모든 고유 번호가 `NORMALIZED` 또는 `REJECTED`라는 뜻이다. `COMPLETED_WITH_ERRORS`는 모든 번호를 순회했지만 실패·미지원·시간 초과가 있다는 뜻이다. 실패 하나가 뒤의 번호 처리를 막지 않는다. 두 상태 모두 실제 프로그램의 취약·안전을 판단한 결과는 아니다.

자식이 종료 코드 0을 반환해도 완료 파일이 없거나 잘못되면 `FAILED / INVALID_CHILD_RESULT`다. 정상·거부 상태는 원본 크기와 SHA-256, 원본 ID·상태, 영수증과 정리 결과의 출처, 기준 이용 고지와 양쪽 고지 및 고지 확인값까지 대조한 후 집계한다. 자식의 터미널 출력이나 CVE 본문을 그대로 출력하지 않는다.

## 중단·저장 실패·시간 제한

`checkpoint.json`은 시작 전, 각 번호 처리 전·후에 임시 파일을 완전히 쓴 뒤 같은 폴더에서 이름을 바꾸는 방식으로 갱신한다. 진행 중에는 `IN_PROGRESS`, Ctrl+C를 처리했을 때는 `INTERRUPTED`다. `activeCveId`는 중단 당시 처리 중이던 번호를 확인하는 데 쓴다. 대기 중이었다면 `null`일 수 있다.

`batch.json`은 전체 번호를 순회하고 마지막 저장까지 성공해야 생긴다. 배치가 완료되어도 체크포인트는 마지막 완료 파일 공개 직전의 `IN_PROGRESS` 상태로 남으므로 최종 집계는 `batch.json`에서 읽는다. `batch.json`이 없으면 항목 개수가 모두 채워졌더라도 완료 배치로 사용하지 않는다. Ctrl+C 때는 실행 중인 자식을 종료·회수하고, 완료 표시를 남기지 않으며 체크포인트를 보존한다. 저장 장치 자체의 오류로 진행 기록도 갱신하지 못할 때는 오류로 종료한다.

번호 하나의 제한 시간에는 네트워크 수신과 정리가 모두 포함된다. 조금씩 응답을 보내 소켓 제한을 피하는 서버라도 부모가 자식 Python을 종료한다. `--timeout`은 0초 초과 300초 이하, `--pause`는 0~300초 범위의 유한한 숫자만 받는다. 건별 시간 제한에 건 사이 대기와 부모의 파일 확인·저장 시간은 포함되지 않는다. 전체 배치 시간 제한은 따로 두지 않는다.

자동 재시도와 중단 지점 재개는 없다. 같은 목록을 다시 실행하면 새 폴더에 처음부터 수집한다. 429 등의 서버 오류도 자동으로 반복 요청하지 않으므로 오류 원인을 확인하고 필요한 번호만 새 목록에 적어 다시 실행한다. 심볼릭 링크를 포함한 입력·출력 경로는 거부한다. 다른 사용자가 동시에 경로를 바꾸는 공격까지 막는 OS 격리 기능은 아니므로 개인 작업 폴더에서 사용한다.

CLI 종료 코드는 다음과 같다.

| 종료 코드 | 뜻 |
| --- | --- |
| `0` | 모든 고유 번호의 처리가 정상·거부 상태로 끝나고 최종 저장을 확인함 |
| `1` | 건별 실패·미지원·시간 초과가 있거나 배치 시작·저장이 실패함 |
| `2` | 필수 인자 누락 등 명령행 사용이 잘못됨 |
| `130` | Ctrl+C 중단을 처리함 |

## 검증

설치된 프로젝트에서 기존 시험과 함께 실행한다.

```bash
.venv/bin/python -m unittest discover -s collector -p 'test_*.py' -v
```

새 `test_batch_cves.py`는 실제 자식 Python, 첫 수집기, 두 번째 정리기와 실제 임시 파일을 사용한다. 공식 서버 통신 경계만 보관한 공개 자료나 합성 실패 응답으로 바꾸므로 시험 자체는 외부 서버를 호출하지 않는다. 느린 수신과 비정상 자식의 도우미 스크립트는 시험용 임시 폴더에만 생성하며 제품에 시험 우회 옵션을 넣지 않는다.

검증 범위에는 중복·입력 전체 검증·크기와 건수 상한, 5.1 보존·미지원 처리, 5.2 거부 기록, 공식 규칙 실패, 통신·JSON 실패 후 계속 처리, 실제 자식의 강제 시간 초과와 취소, 재실행 보존, 저장·이름 변경 실패, 위조·누락 자식 결과, 수집 후 원본·고지 변조, 종료 코드, 심볼릭 링크가 포함된다. 심볼릭 링크를 만들 권한이 없는 Windows에서는 해당 시험 한 개를 건너뛰며 Linux VM에서 다시 확인해야 한다.

시험에서 파생한 ID·내용은 합성 자료이며 새로운 공개 CVE를 수집한 증거가 아니다. VM에 적용했다는 확인은 실제 VM 출력으로 별도 확인해야 한다. 이 기능은 메타데이터를 요청할 뿐 npm 설치나 취약 라이브러리 실행을 하지 않는다.

## 이용 조건

CVE 원본과 `CVE_LICENSE_NOTICE.txt`, 수집 영수증의 출처·조회 시각을 함께 보관한다. 공식 스키마와 Python 의존성의 기존 고지도 유지한다. SYSsecurity 코드의 MIT 조건이 CVE 자료·공식 스키마·의존성의 원래 이용 조건을 바꾸지 않는다. 세부 조건은 앞 단계의 고지 파일과 `README-step2.md`를 따른다.
