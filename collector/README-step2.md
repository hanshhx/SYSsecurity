# v0.4 두 번째 단계: CVE 형식 검사와 항목 정리

이미 받아 둔 CVE 한 건을 읽어 공식 파일 규칙을 확인하고, 프로그램·버전·위험 점수를 출처별로 정리한다. 이후 실제 설치된 프로그램과 대조할 때 사용할 자료를 준비하는 단계이다.

## 첫 단계와의 차이

| 첫 단계 | 이번 단계 |
|---|---|
| 공식 API에서 CVE 한 건을 받음 | 기존 수집 폴더를 읽음. 다시 다운로드하지 않음 |
| 번호·형식 버전·공개 상태 등 기본 구조 확인 | 공식 CVE 파일 규칙에 따른 필수 항목·자료형·주소 등 확인 |
| 원본·조회 시각·SHA-256·고지 보관 | 원본 확인값을 대조하고 기관별 정보와 누락 항목을 정리 |
| `receipt.json`을 마지막에 저장 | 새 폴더의 `normalized.json`을 마지막에 저장 |

공식 규칙을 통과했다는 것은 **파일 구조가 규칙에 맞는다**는 뜻이다. CVE 내용이 모든 환경에서 사실인지, 현재 컴퓨터에 영향을 주는지, 실행을 막아야 하는지까지 확인한 결과가 아니다.

## 추가한 파일

| 파일 | 역할 |
|---|---|
| `normalize_cve.py` | 원본 확인 → 공식 규칙 검사 → 기관별 정리 → 새 결과 저장 |
| `test_normalize_cve.py` | 누락·잘못된 입력·원본 변경·저장 실패·정보 보존 시험 |
| `requirements-step2.txt` | 검사에 필요한 Python 패키지 7개의 정확한 버전과 파일 확인값 |
| `DEPENDENCY_LICENSES.txt` | 해당 패키지의 원래 저작권·이용 조건 |
| `fixtures/` | 공식 CVE 한 건의 고정 시험용 사본, 출처와 이용 고지 |
| `schemas/cve-5.2.0/` | 공식 규칙 원문, 출처·확인값, CC0 및 포함 CVSS 자료의 이용 고지 |

기존 `fetch_cve.py`, 기존 시험, CVE 이용 고지는 변경하지 않는다. 설치 파일에 이 세 파일의 같은 사본을 포함한 것은 기존 코드가 확인했던 코드와 같은지 비교하기 위해서이다.

## 실행 방법

프로젝트 폴더에서 실행한다. 수집 폴더에는 첫 단계가 만든 원본·완료 기록·이용 고지가 있어야 한다.

```bash
.venv/bin/python collector/normalize_cve.py reports/cve/CVE-2025-55130-w4aslzgu
```

결과는 입력 폴더 안의 새 `normalized-v1-임의문자/` 폴더에 저장된다. 기존 원본·완료 기록·이전 정리 결과를 덮어쓰지 않는다. 완료 파일은 `normalized.json`이며, 그 옆에 CVE 이용 고지가 있다. `normalized.pending.json`만 있는 폴더는 중간에 멈춘 것이므로 사용하지 않는다.

반복 시험은 다음과 같다. 실제 API 요청이나 취약 프로그램 실행은 포함하지 않는다.

```bash
.venv/bin/python -m unittest discover -s collector -p 'test_*.py' -v
```

## 결과를 읽는 방법

| 결과 항목 | 쉽게 읽는 뜻 |
|---|---|
| `formatVersion` | SYSsecurity 정리 결과의 형식 이름. CVE 원본의 형식 버전과 다름 |
| `cveId`, `recordState` | CVE 번호와 공개·거부 상태 |
| `recordMetadata`, `dataVersion` | 원본의 번호 관리 정보와 파일 형식 버전 |
| `source` | 원본 주소·가져온 시각·바이트 수·원본 확인값·이용 조건 주소 |
| `validation` | 어느 공식 규칙과 어느 검사 도구 버전으로 확인했는지 |
| `sources` | CNA와 각 ADP가 제공한 정보를 별도 묶음으로 보존 |
| `products` | 기관별 프로그램 항목. 제품 이름·버전·상태·범위를 원문 그대로 보존 |
| `metrics` | 점수와 기타 평가를 포함한 원래 평가 묶음 전체 |
| `scores` | CVSS 2.0·3.0·3.1·4.0 점수가 있으면 출처별로 따로 모음 |
| `missingFields` | 이 정리 단계에서 확인한 주요 항목 중 원문에 없는 항목 이름 |
| `readyForMatching` | 현재는 항상 `false`. 실제 프로그램 대조 준비 완료라는 뜻으로 쓰지 않음 |

`path`는 원본 JSON 안의 정확한 위치이다. 예를 들어 `/containers/adp/1/affected/0`은 두 번째 ADP의 첫 프로그램 항목이다. 같은 기관이 여러 묶음을 제공해도 이 위치로 구분하므로 덮어쓰지 않는다. `sourcePath`는 어떤 기관 정보에서 가져왔는지를 연결한다.

`data`에는 해당 항목의 원래 내용을 보존한다. 설명·참고 링크·해결 방법·일시·추가 항목 등은 각 `sources[].information`에 보존한다. 같은 이름의 정보가 기관마다 있어도 합치지 않는다. `missingFields`는 모든 필수 항목의 오류 목록이 아니다. 필수 항목 오류는 먼저 공식 규칙 검사에서 거부한다. 이 목록은 유효한 파일에서 선택 정보가 빠진 사실을 표시한다.

## 실제 시험 자료에서 확인한 점

고정해 둔 CVE-2025-55130 사본은 기관별 정보 3묶음, 프로그램 항목 17개, 버전 항목 22개, 평가 묶음 4개, CVSS 점수 2개를 포함한다. 이것은 CVE 17건 또는 설치한 프로그램 17개라는 뜻이 아니다. 파일 안에 기관들이 작성한 항목 수이다.

- CNA의 Node.js 정보와 Red Hat 패키지 정보를 분리한다. Red Hat의 RPM 버전 문자열을 npm 버전으로 바꾸지 않는다.
- `version`과 `lessThanOrEqual`이 둘 다 `20.19.6`이면 그대로 저장한다. 임의로 “20 버전 전체”나 “20.19.6 이하 전부”로 늘리지 않는다.
- `lessThan`과 `lessThanOrEqual`은 끝 버전 포함 여부가 다르므로 원래 이름을 보존한다. `changes`에 들어 있는 중간 상태 변경도 보존한다.
- 점수가 없으면 0점으로 채우지 않는다. 정보가 없다는 이유로 안전하다고 판정하지 않는다.
- `PUBLISHED`와 `REJECTED`를 구분한다. 거부 기록도 이유를 보관하지만 검사 후보나 실행 허용 근거로 쓰지 않는다.
- 실제 공식 기록이 나중에 바뀌어도 회귀 시험의 입력은 그대로 유지한다. 새 원본과 비교하는 작업은 별도로 수행한다.

## 확인하는 범위와 남은 범위

1. 원본 크기·SHA-256이 완료 기록과 같은지 확인한다. SHA-256은 전자서명이 아니므로 원본과 완료 기록을 함께 바꾸는 공격을 막는 인증 수단은 아니다.
2. 원본 번호·상태·파일 버전과 수집 기록이 맞는지 확인한다. 이용 고지도 설치된 원문과 일치해야 한다.
3. 공식 v5.2.0 bundled 규칙의 고정 확인값을 확인한다. 처음에는 원본 `dataVersion="5.2"`만 지원한다. `5.0`, `5.1`, `5.2.0`, 미래 버전은 다음 지원 작업 전까지 거부한다.
4. 공식 규칙이 정한 필수 항목·자료형·범위·주소 형식을 검사한다. 날짜도 해당 항목에 지정된 공식 규칙 범위에서 검사하며, 모든 날짜의 달력상 유효성이나 날짜 사이 선후 관계까지 검증했다고 뜻하지 않는다.
5. 입력·정리 과정에서 네트워크 요청을 하지 않는다. 모든 규칙 참조는 함께 제공한 파일 내부에서 처리한다.

아직 실제 설치 프로그램의 확인, 버전 범위 대조, 점수 선택 정책, 사용자 경고, 실행 허용·차단은 구현하지 않았다. CVE 60~100건 수집 목표도 유지된다. 이번 단계는 그 전에 한 건의 처리 경로를 확인하는 작업이다. 전체 v0.4 완료 전에는 제품 버전을 0.4.0으로 올리지 않는다.

## 오류가 나면

- `INTEGRITY_MISMATCH`: 원본이 수집 당시 크기·확인값과 다름. 원인을 먼저 확인한다.
- `SCHEMA_INVALID`: 공식 파일 규칙에 맞지 않음. 원본을 임의로 고쳐 성공으로 만들지 않는다.
- `UNSUPPORTED_FORMAT`: 이 단계에서 아직 지원하지 않는 형식 버전임.
- `INVALID_RECEIPT`, `RECEIPT_MISMATCH`: 완료 기록이 없거나 원본과 다름.
- `NOTICE_MISMATCH`: 이용 조건 파일이 원문과 다름.
- `INVALID_UNICODE`: JSON을 읽은 뒤 UTF-8로 보존할 수 없는 문자 값이 있음.
- `STORAGE_ERROR`: 읽기·저장 실패. 완료 파일이 없으면 성공 자료로 사용하지 않는다.
- `UNSAFE_INPUT_PATH`: 심볼릭 링크가 있는 경로임. 실제 수집 폴더를 지정한다.

이 기능은 본인 작업 폴더에서 쓰는 자료 정리 기능이다. 다른 사용자가 동시에 파일 경로를 바꾸는 공격까지 막는 운영체제 격리 기능은 아니다. 실제 취약 프로그램 실행은 이후에도 본인 VM에서만 수행한다.
