# 패키지 이름과 버전으로 OSV 자료 받기

## 왜 필요한가

기존 수집기는 CVE 번호를 미리 알아야 자료를 받을 수 있었음. 이제 `tar`의 `6.1.0` 버전처럼 프로그램 부품의 이름·버전을 입력하면 OSV가 연결한 취약점 기록을 가져옴. 이번 작업은 자료 수집임. 실제 설치 목록 조사·위험 판단·실행 차단은 후속 단계임.

## 사용

프로젝트 폴더에서 아래 명령을 실행함. 기존 프로젝트 전용 Python 환경과 고정한 의존성이 필요함.

```bash
.venv/bin/python collector/query_osv.py --package tar --version 6.1.0
```

`latest`, `>=6` 같은 범위 대신 정확한 버전을 입력함. 첫 지원 대상은 npm임. Python만 실행하며 `tar`를 설치하거나 취약한 코드를 실행하지 않음.

## 진행 순서

1. 이름·버전이 지원하는 입력인지 확인함.
2. 공식 OSV 조회 주소에 요청함. 다음 페이지 표시가 있으면 같은 대상으로 계속 받음.
3. 각 기록을 OSV 공식 구조와 대조함. 원문과 정보를 정리한 결과를 새 폴더에 저장함.
4. 별도 수집 작업이 끝나면 원본·확인값·고지·정리 결과를 다시 읽어 대조함.
5. 전부 맞을 때만 `result.json`을 만들고 `OSV_QUERY_COMPLETE`를 출력함. 이 문구는 직접 입력하는 명령이 아님.

## 결과 파일 읽기

매번 `reports/osv/query-임의문자/`가 새로 생김. 이전 결과는 보존함.

| 파일·항목 | 의미 |
|---|---|
| request.json | 조회한 패키지 이름과 버전 |
| page-0001.json 등 | 서버가 반환한 원본. 여러 페이지면 번호별로 보존함 |
| draft-result.json | 수집 작업이 작성한 중간 결과. 최종 성공 파일이 아님 |
| result.json | 원본까지 다시 대조한 최종 조회 결과 |
| failure.json | 실패 이유. 중간 자료가 남아 있어도 완료가 아님 |
| worker.log | 수집 작업의 오류 확인용 기록 |
| GHSA_CC_BY_4_0.txt, OSV_DATA_NOTICE.txt | 확인한 출처의 이용 조건 원문과 출처·변경 고지 |
| records[].data | 받은 각 기록의 전체 항목. 버전 범위·평가 문자열도 보존함 |
| cveIds | OSV 기록의 별칭에 들어 있는 CVE 번호 목록 |
| missingFields / issues | 빠진 정보와 추가 확인이 필요한 부분 |
| matchingPackageIndexes | 원문에서 이름·생태계가 요청과 같은 항목 위치. 버전 영향 판단 결과가 아님 |
| readyForMatching=false | 자체 설치 목록·정확한 버전 비교와 아직 연결하지 않았다는 표시 |

조회 완료는 “안전함”이 아님. 0건은 서버에서 조회된 기록이 없다는 뜻임. `ACTIVE`도 실제 공격 성공을 뜻하지 않음. `WITHDRAWN`은 철회 표시이며, 자동 차단 근거로 바로 쓰지 않음. 점수가 없으면 0점을 넣지 않음. 같은 CVE가 여러 OSV 번호에 연결될 수 있으므로 원래 번호별 기록을 보존함.

## 이용 조건

OSV는 여러 기관의 자료를 제공함. 모든 자료의 이용 조건이 같지는 않음. 이번에는 GitHub Advisory Database의 GHSA 기록에 대해 CC BY 4.0 원문·출처·변경 내용을 함께 제공함. 다른 출처는 `LICENSE_REVIEW_REQUIRED`로 남기므로 별도 확인 전 재배포가 허용된다고 추정하지 않음. 참고 링크의 코드에도 별도 이용 조건이 적용됨.

정리한 기록은 원문을 `data` 아래로 옮기고 조회 맥락을 추가한 자료임. 각 페이지 원본은 그대로 보존함. 출처가 SYSsecurity를 보증한다는 뜻은 아님.

## 제한과 실패 처리

한 페이지 2 MiB, 전체 원본 20 MiB, 100페이지, 고유 기록 10,000건, JSON 중첩 64단계, 전체 조회 180초를 초기 처리 제한으로 둠. 제한에 걸리면 일부만 받은 상태를 성공으로 표시하지 않음. 페이지 사이에는 1초 간격을 둠. 재실행은 새 폴더에서 처음부터 조회하며 자동 이어받기·자동 재시도는 이번 범위가 아님.

지원 형식은 OSV 1.0.x~1.9.x임. 형식 표시가 없으면 공식 규칙에 따라 1.0.0으로 읽음. 규칙 파일은 확인한 원문 사본과 확인값을 고정함. OSV 자체의 버전 조회 결과가 우리 프로그램의 정확한 버전 판정을 대신하지 않음.

## 시험

```bash
.venv/bin/python -m unittest discover -s collector -p 'test_*.py' -v
```

가상 응답으로 여러 페이지·빈 결과·철회·누락·중복·변경 충돌·실패를 시험함. 실제 서버 연결은 별도 확인하며, Windows 결과만으로 Ubuntu에서 확인했다고 기록하지 않음.
