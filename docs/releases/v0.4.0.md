# v0.4.0 — 공식 취약점 자료 수집·정리

검증 확인일: 2026-10-01


- CVE 번호 목록이나 npm 패키지 이름·버전으로 공식 취약점 자료를 받을 수 있게 함.
- 원본·출처·이용 조건을 보존하고, 철회·정보 누락·수집 실패를 구분해 저장함.
- Ubuntu에서 수집 시험 110개·기존 기능 시험 5개·빌드를 통과했고, 실제 OSV 조회 18건의 저장 내용도 확인함.

**문제 → 원인 → 해결 → 결과**

예상과 다른 서버 응답을 “조회 결과 0건”으로 처리할 수 있었음 → 목록 항목이 없으면 빈 목록으로 읽었기 때문임 → 지원하는 응답 구조인지 먼저 확인하도록 바꿈 → 오류 응답은 실패로 남기고 정상적인 빈 응답은 유지하는 시험이 통과함. 이 문제는 가상 응답으로 재현한 것이며 실제 OSV 서버 장애가 발생했다는 뜻은 아님.

<details>
<summary>추가한 기능과 확인 범위</summary>

- CVE 한 건 수집, 여러 번호 순차 처리, 공식 항목 구조 확인, 필요한 정보 정리를 연결함.
- CVE 5.1·5.2 기록을 각각 고정한 공식 규칙과 대조함. 원문 형식·사용한 규칙 버전을 따로 보존함.
- npm 이름·정확한 버전으로 OSV를 조회하고 다음 페이지가 있으면 계속 받음.
- 통신 중단·잘못된 파일·시간 및 크기 제한·중복과 내용 충돌·저장 실패를 완료로 처리하지 않음.
- 매번 새 결과 폴더를 만들어 이전 자료를 보존함. 원본 파일의 확인값, 조회 시각, 출처와 이용 조건을 함께 남김.
- Ubuntu 수집 시험 110개와 기존 RELAPSE 예제 시험 5개는 실패·건너뜀 없이 통과함. 실제 `tar@6.1.0` 조회에서 OSV 기록 18건을 받았으며, 받은 원문과 정리 결과가 일치했음. 기록 수는 조회 시점에 따라 달라질 수 있음.
- 첫 지원 대상은 npm임. OSV 결과가 없다는 사실만으로 안전하다고 판단하지 않음. 다른 출처의 이용 조건은 별도로 확인해야 함.
- 설치된 프로그램 목록 확인, 자체 버전 영향 비교, 경고·실행 차단은 후속 버전임. 이번 결과의 `readyForMatching=false`는 그 연결이 아직 없다는 뜻임.

사용 예시:

```bash
.venv/bin/python collector/query_osv.py --package tar --version 6.1.0
```
