# v0.4 개발 중 기록

> 아래는 개발 당시의 기록임. 현재 기능과 확인 결과는 상위 README 및 CHANGELOG를 기준으로 읽음. 당시 미지원·확인 대기 상태를 이력으로 보존함.

## 미배포 — v0.4 개발 중: CVE 단건 수집

### 한 일
- 공식 API에서 CVE 한 건을 받아 기본 구조·번호·공개 상태를 확인하고 원본·출처·조회 시각·SHA-256·이용 고지를 저장하는 코드를 추가함.
- 성공한 저장만 receipt.json으로 표시하고 통신·형식·저장 실패를 별도로 기록함. 거부 기록도 보존하되 모든 자료는 아직 실행 판단에 연결하지 않음.
- Python 표준 기능으로 구현하며 외부 pip 패키지는 사용하지 않음. 기존 TypeScript 검사기 규격과 제품 버전 0.3.0을 유지함.

### 겪은 문제와 해결
- 응답 읽기 중 연결 끊김이 저장 실패로 분류됨 → 통신과 파일 입출력 오류를 같은 위치에서 처리했음 → 통신 구간에서 NETWORK_ERROR로 구분함.
- 비정상적으로 긴 응답 길이 숫자와 잘못된 입력 형식이 예외를 일으킴 → 변환 전 확인이 부족했음 → 길이·문자열 여부를 먼저 확인함.

### 확인 범위
- Windows 준비 과정에서 테스트 17개 중 16개 통과, 심볼릭 링크 1개는 권한 부족으로 건너뜀. 공식 API 실제 단건 저장도 확인함.
- Ubuntu에서는 함께 제공한 적용 스크립트로 테스트와 실제 수집을 확인해야 함. 전체 형식 검사·정보 정리·OSV 연결·실행 보호·v0.4 릴리즈 완료를 뜻하지 않음.


## 미배포 — v0.4 개발 중: 공식 형식 검사와 항목 정리

### 한 일
- 첫 단계의 원본과 수집 기록을 대조하고, CVE 공식 v5.2.0 규칙으로 dataVersion 5.2 자료를 검사하는 기능을 추가함.
- 프로그램·버전·점수를 기관별로 분리하고 누락된 항목·출처·이용 고지를 함께 저장함. 점수 선택·영향 버전 계산·실행 차단은 다음 단계임.
- Python 검사 패키지 7개의 버전·해시와 공식 규칙 파일을 고정함. 기존 TypeScript 규격·제품 버전 0.3.0을 유지함.

### 겪은 문제와 해결
- 공식 bundled 규칙 안의 CVSS 고지가 따로 보존되지 않음 → 저장소 공통 이용 조건만으로 포함된 자료를 설명하기 어려움 → CVSS 원문 고지와 Python 의존성 고지를 함께 제공함.

### 확인 범위
- 실제 CVE-2025-55130 기록을 회귀 시험에 사용함. 원본 변조·형식 오류·누락·기관별 정보 보존·저장 실패를 시험함.
- Ubuntu 실행 결과는 설치 스크립트의 시험 출력과 성공 표시로 별도 확인함. 이 변경 기록 자체는 VM 확인 또는 전체 v0.4 릴리즈 완료 증거가 아님.


## 미배포 — v0.4 개발 중: 목록 수집과 건별 결과 기록

### 한 일
- CVE 번호 목록의 오류·중복을 먼저 확인하고 기존 수집기와 정리기를 차례로 실행하도록 추가함.
- 정상 정리·철회·미지원 형식·실패·시간 초과를 구분해 진행 기록과 최종 결과를 저장함. 이전 결과는 보존함.
- 한 건이 실패해도 나머지를 처리하고, 실패가 있는 배치는 정상 성공으로 종료하지 않음. 건별 별도 Python 실행에 시간 제한을 둠.
- 기존 TypeScript 코드·수집기·정리기·공식 규칙·Python 의존성과 제품 버전 0.3.0을 유지함.

### 겪은 문제와 해결
- 기존 수집기의 소켓 대기 제한만으로 전체 수집 시간을 보장할 수 없음 → 배치 호출부에서 건별 Python 프로세스에 전체 실행 제한을 적용함.
- 일부 기록이 실패했는데 전체가 성공한 것으로 보일 수 있음 → 건별 상태·개수·완료 상태·종료 코드를 함께 남김.

### 확인 범위
- 공식 CVE 3건은 소량 연결 확인용이며 최종 60~100건 확보·실제 설치 프로그램 대조·실행 차단 완료가 아님.
- 현재 정리는 dataVersion 5.2만 지원함. 다른 형식을 조용히 받아들이지 않음. readyForMatching은 false를 유지함.
- Ubuntu 완료는 설치 파일의 시험 출력과 성공 표시로 별도 확인함. 전체 v0.4 릴리즈 완료 기록이 아님.


## 미배포 — v0.4 개발 중: CVE 5.1 형식 지원 추가

### 핵심 요약
- 기존 5.2와 함께 5.1 자료도 각 형식에 맞는 공식 규칙으로 확인하고 정리하도록 확장함.
- 원본·수집 기록·정리 결과의 형식과 규칙 출처가 서로 맞는지 확인함.
- 실제 CVE-2021-32803을 시험 예제로 추가함. 전체 v0.4 완료와 실행 보호 구현을 뜻하지 않음.

### 문제 하나와 해결 과정
- 문제: 새 규칙 정보를 시작 시점에 불러오자, 정리기 파일이 없는 상황에서 기존 오류 안내가 달라졌음.
- 원인: 기존 오류 처리에 도달하기 전에 필요한 파일을 불러오다 실패했음.
- 해결: 성공 결과를 확인할 때만 규칙 정보를 불러오도록 바꿈.
- 결과: 누락된 파일을 MISSING_DEPENDENCY로 알리는 기존 시험을 다시 통과함.

### 확인 범위
- 로컬 전체 시험 결과와 Ubuntu 적용 결과는 전달 묶음의 verification-summary.json 및 실제 실행 출력으로 구분함.
- 형식 검사는 취약점 재현이나 실행 허용·차단 판정이 아님. readyForMatching=false를 유지함.


## 미배포 — v0.4 개발 중: 패키지 이름과 버전으로 OSV 자료 조회

- CVE 번호를 몰라도 npm 패키지 이름과 정확한 버전으로 관련 OSV 자료를 받을 수 있게 함.
- 다음 페이지까지 받고, 원본·조회 시각·출처·이용 조건을 새 폴더에 보존함.
- 빈 결과·철회·항목 누락·중간 실패를 구분함. 프로그램의 안전 판정이나 실행 차단은 아직 수행하지 않음.

**문제 → 원인 → 해결 → 결과**

기존에는 CVE 번호를 미리 알아야 자료를 받을 수 있었음 → 수집 입력이 CVE 번호였기 때문임 → 패키지 이름·버전으로 조회하는 별도 기능을 추가함 → 공식 OSV 조회와 원본 대조를 설치 확인 과정에서 시험하도록 함.
